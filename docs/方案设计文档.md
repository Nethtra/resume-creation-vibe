## 1. 一句话定位

**免费、无水印、ATS 友好、数据不出浏览器的在线简历工具**，面向应届生和初级求职者。
核心路径三步：填信息 → 选模板 → 导出 PDF。不注册、不登录、不上传。

两个差异化卖点（所有商业竞品的软肋）：
1. **隐私**：纯前端应用，简历数据只存浏览器 localStorage，全站无统计、无接口请求；
2. **ATS**：导出的 PDF 是真实文本层（可选中、可检索、单栏逻辑顺序），机筛系统解析不丢内容。

## 2. 调研结论（为什么这么做）

| 项目 / 网站 | 定位 | 技术栈 | PDF 方案 | 协议 / 收费 | 对本项目的启示 |
|---|---|---|---|---|---|
| Reactive Resume（44.8k★） | 全功能简历平台 | Next.js + NestJS + PostgreSQL + Docker monorepo | 服务端渲染 | MIT / 免费 | 功能蓝本；但需要数据库和后端，**太重，不适合 fork** |
| OpenResume（8.9k★） | 纯前端 ATS 简历工具 | React + TS + **@react-pdf/renderer** | 库端生成真文本 PDF | **AGPL-3.0** / 免费 | 技术路线已被验证可行；若 fork 源码需整体遵守 AGPL 开源 |
| dnd-resume（1.4k★，中文） | 轻量在线简历 | Vite + React + Tailwind + shadcn | **浏览器打印**导出 | AGPL-3.0 / 免费 | 证明中文轻量方案可行；但打印导出在手机上体验差、分页不可控 |
| 萝卜简历 / 老鱼简历（商业站） | 模板墙 + 云编辑 | 闭源 | 导出带水印或收费 | 免费模板 + 会员制 | 免费额度普遍有水印/导出墙，**"真免费 + 本地隐私"是空位** |
| Canva 简历 | 设计平台品类之一 | 闭源 | 图形化 PDF | 部分收费 | 排版华丽但**图形化 PDF 对 ATS 不友好**，反衬我们的定位 |

**三条核心结论：**
1. **排版和 PDF 渲染不必从零造轮子**——`@react-pdf/renderer` 是成熟开源库（React 组件写排版 → 生成真文本 PDF，支持注册中文字体），OpenResume 已验证这条路线；
2. **不建议整站 fork 开源项目**——重型项目（Reactive Resume）的理解和裁剪成本高于轻量自研；OpenResume/dnd-resume 是 AGPL 协议，直接二开会把整个项目绑定成 AGPL 开源。我们**参考它们的设计思路，代码独立实现**（技术选型不受 AGPL 约束，库本身按其协议正常使用）；
3. 国内商业站共同软肋 = 收费水印 + 数据上云 + 图形化 PDF，这三点正好是我们的卖点。

## 3. 技术架构

### 3.1 总体：纯前端 SPA，v1 零后端

```
浏览器（一切发生在这里）
┌─────────────────────────────────────────────┐
│  React SPA（Vite 构建静态文件）                │
│  ├─ 页面：首页 / 编辑器 / 模板选择              │
│  ├─ zustand store ⇄ localStorage（自动保存）   │
│  ├─ HTML 实时预览（编辑时所见）                 │
│  ├─ @react-pdf/renderer → 导出真文本 PDF       │
│  └─ DOM→Canvas → 导出 PNG（预览分享用）         │
└─────────────────────────────────────────────┘
        ↓ 构建产物只是一堆静态文件
   静态托管（Vercel / GitHub Pages，零服务器）
```

没有后端、没有数据库、没有登录。未来若做账号和云同步，加一个轻后端即可，数据模型不变。

### 3.2 技术选型

| 用途 | 选择 | 一句话理由 |
|---|---|---|
| 构建框架 | **Vite 6 + React 18 + TypeScript** | 轻量快速，比 Next.js 简单；SEO 需求不大，首页做好 meta 即可 |
| 样式 | **Tailwind CSS v4** | 设计 tokens 走 CSS 变量，瑞士风格用工具类表达很直接 |
| 状态/存储 | **zustand + persist 中间件** | 极简状态库，persist 一行配置实现 localStorage 自动保存，带版本号方便以后迁移 |
| 路由 | react-router v7 | 三个页面：`/`、`/editor`、`/templates` |
| **PDF 导出** | **@react-pdf/renderer** | 见 3.4 的方案对比 |
| PNG 导出 | ~~modern-screenshot~~ → **pdf.js 光栅化 PDF** | M2 实测 DOM 截图在构建产物下无法可靠嵌入 webfont（文字重叠），改为从 PDF 光栅化，与 PDF 同源渲染 |
| 图标 | lucide-react | SVG 图标，杜绝 emoji 当图标 |
| 字体 | 界面：Poppins（拉丁）+ 系统中文（苹方/雅黑）；标题衬线：Lora；**PDF 内嵌：Noto Sans SC 子集** | 中文 webfont 体积大，界面用系统字体零成本；PDF 需要可嵌入的开源字体（Noto Sans SC 是 OFL 协议，允许嵌入分发） |

### 3.3 简历数据模型（JSON）

单一 JSON 对象存整份简历，结构对齐国际通用的 **JSON Resume 标准**并做扩展，方便将来兼容其他工具导入：

```json
{
  "basics": { "name": "张小明", "target": "前端开发工程师（2027届）",
              "phone": "138-0000-0000", "email": "...", "links": ["github.com/..."] },
  "education":  [{ "school": "某某大学", "degree": "本科 · 计算机科学与技术",
                   "start": "2023.09", "end": "2027.06", "highlights": ["GPA 3.6/4.0"] }],
  "work":       [{ "company": "某科技公司", "role": "后端开发实习生",
                   "start": "2026.03", "end": "2026.06", "bullets": ["负责订单模块接口开发，将查询接口平均响应时间从 800ms 降至 120ms"] }],
  "projects":   [{ "name": "在线简历编辑器", "role": "独立开发", "start": "2026.09", "end": "至今", "bullets": ["..."] }],
  "skills":     ["Java / Spring Boot", "JavaScript / React", "MySQL", "Redis", "CET-6"],
  "summary":    "自我评价文本",
  "meta":       { "template": "classic", "accent": "#191919", "schemaVersion": 1 }
}
```

**导入/导出 JSON 按钮** = 数据自主权（换电脑、备份、将来云同步都靠它），也是隐私承诺的一部分。

### 3.4 PDF 导出方案对比（核心决策）

| 方案 | 文本可选中(ATS) | A4 分页控制 | 手机可用 | 中文字体 | 代价 |
|---|---|---|---|---|---|
| **A. @react-pdf/renderer（推荐）** | ✅ 真文本 | ✅ 精确到 mm | ✅ | 需构建期子集化 Noto Sans SC（~2MB，首次导出时懒加载） | 预览(HTML)与 PDF(库)是两套渲染，需用同一数据源+截图比对保证一致 |
| B. 浏览器打印（dnd-resume 路线） | ✅ 真文本 | ⚠️ 分页易失控 | ❌ 打印对话框在手机上很难用 | 用系统字体，零成本 | 零依赖，但体验上限低 |
| C. html2canvas + jsPDF | ❌ **图片化，ATS 不友好** | — | — | — | **明确排除**——不少商业站这么干，恰是我们的反面 |

推荐 **A**：`@react-pdf` 已确认支持 `Font.register` 注册自定义 TTF（含中文字体），PDF 内是真实文本层。若 M2 实测双渲染一致性成本过高，退路是 OpenResume 的"预览即 PDF"模式（预览直接渲染 PDF），在 M2 内做取舍。

### 3.5 隐私承诺怎么落实（不是一句口号）

- 全站静态文件，**没有任何后端接口**，浏览器 Network 面板可验证；
- 无统计埋点、无 CDN 请求（字体全部自托管）；
- 数据只在 localStorage，提供「导出 JSON 备份」和「清除我的数据」两个入口；
- 断网状态下整个编辑器仍可用；
- 首页专属声明条 + 编辑器顶栏常驻"已自动保存 · 本地"。

## 4. UI 设计方向（Swiss Style × claude.com 实测）

### 4.1 claude.com 实测结论（浏览器实际访问提取）

- 配色：**暖白 #FAF9F5 / 近黑 #141413**，整站只有一个强调色（实测 logo 橙红 `rgb(217,119,87)` = **#D97757**）；
- 字体：**衬线大标题（细字重 330、56px）+ 无衬线正文**，衬线承担"人文感"，无衬线承担"工具感"；
- 版面：大留白、细分割线（hairline）、平涂大圆角卡片、居中大标题区块（FAQ）、勾选列表；
- 没有渐变、没有阴影堆砌、没有插画装饰——和瑞士风格同源。

### 4.2 设计 tokens（Claude 气质 + 你指定的暖白/近黑/红）

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#FAF9F5` 暖白 | 页面底色（纸的感觉） |
| `--surface` | `#FFFFFF` | 卡片、表单面板 |
| `--ink` | `#191919` 近黑 | 正文与标题 |
| `--ink-2` | `#6E6A63` | 次级文字、说明 |
| `--line` | `#E5E2DA` | 1px 分割线、描边 |
| `--accent` | `#D97757` 陶土橙（已确认，claude.com 同款） | logo、装饰图标、色块标记 |
| `--accent-strong` | `#B85C3F`（加深版） | 小字文本、按钮填充——保证对白底对比度 ≥ 4.5:1 |
| `--ok` | `#16A34A` | 仅 ATS 检查通过的反馈态 |

- 字体阶梯：12 / 14 / **16(正文)** / 20 / 28 / 40 / 56px；正文行高 1.5，大标题 1.15；标题用 **Lora 衬线**，界面用 **Poppins + 系统中文**；
- 间距：8pt 网格（4/8/12/16/24/32/48/64/96）；
- 组件：卡片圆角 12px、按钮 8px、**全站无阴影**（平涂）、hover 只做背景微变（200ms）、焦点态清晰可见；
- 反面清单：无渐变、无阴影、无插画、无大动画（只保留 300ms 级淡入）、不用 emoji 当图标、不堆花哨 hover。

> 交互细节遵循 ui-ux-pro-max 规范：44px 触控目标、错误就近提示、`prefers-reduced-motion` 降级、对比度 ≥ 4.5:1。已生成 `design-system/plainresume/MASTER.md`（其中数据库默认的藏蓝色板**不采纳**，以上方 tokens 为准）。

### 4.3 关键页面

**① 首页**（说服页，转化目标只有一个：点"开始制作"）
顶栏（左 wordmark：红点 + 素页简历；右：模板 / 隐私说明 / GitHub / 红色 CTA）→
hero 不对称两栏（左：衬线大标题"不用注册，不收钱，三分钟做出能过机筛的简历" + 双按钮；右：真实简历纸样预览）→
三卖点网格（数据不出浏览器 / ATS 友好导出 / 真免费无水印）→ 模板缩略图条 → **红边隐私声明条** → FAQ → 极简 footer。

**② 编辑器**（效率工具）
顶栏（返回 / "已自动保存 · 本地" / 导入 JSON / 导出 PNG / **红色导出 PDF**）→
左表单手风琴（基本信息·求职意向·教育·实习/工作·项目·技能证书·自我评价，带"必填/已填 n 条"标签）×
右 A4 实时预览（缩放自适应 + 模板切换 Tab + 主题色圆点）→
移动端折叠为「填写 / 预览」双 Tab。

**③ 模板选择**
v1 共 3 套，全部 ATS 安全（单栏或顺序明确的双栏，不用表格布局）：
「经典单栏」（默认，最 ATS）、「双栏简洁」、「极简衬线」。

### 4.4 模板设计规范（回应"模板要好看、要实用"）

完成度对标国内商业站热门模板（老鱼/萝卜模板墙水平）：照片位、彩色标题、图标、技能标签、清晰层级，一个都不少。M0 起首页即使用精修版简历卡，不允许停留在低保真线框水平。

**放心用的装饰（ATS 解析完全无感）**：颜色与色块标题、装饰性 SVG 图标（联系方式本身仍是真文本）、照片（ATS 直接忽略，默认开启、可一键关闭）、技能标签 chips、字号/字重层级、右对齐日期、留白节奏。

**明确避开（真会伤 ATS）**：文字烧进图片、表格/多列嵌套布局、阅读顺序与视觉顺序不一致的双栏、页眉页脚藏正文、仅用图形表达信息（如不带文字等级的技能进度条）。

## 5. 开发计划（5 个里程碑，每步都有能跑的东西）

| 里程碑 | 内容 | 你能看到什么 | 验收标准 |
|---|---|---|---|
| **M0 地基**（1 次交付） | 脚手架 + 设计 tokens + Tailwind 配置 + 首页整页 | 浏览器打开首页，三端截图给你 | 375/768/1440 三档无横向滚动，Lighthouse 性能/无障碍 ≥ 90 |
| **M1 编辑器核心** | 表单 + zustand + localStorage 自动保存 + 单模板 HTML 预览 + JSON 导入导出 | 左边填字右边预览跟着变，刷新不丢 | 浏览器自动化跑通"填数据→预览更新→刷新仍在→导出 JSON 再导入"全流程 |
| **M2 导出**（核心卖点） | @react-pdf/renderer + 中文字体子集懒加载 + PDF/PNG 导出 + 文本层自检 | 点一下得到真文本 PDF，手机上也能导 | PDF 提取文本与预览一致、可选中；中文无乱码；与 HTML 预览截图比对 |
| **M3 补全** | 3 套模板 + 首页完善 + 移动端体验 + ATS 自检清单面板 | 模板一键切换，手机可编辑 | 每模板三端截图通过；ATS 清单项全部可验证 |
| **M4 打磨发布** | 错误边界 + 空状态 + README + 部署 | 上线一个可公开访问的网址 | Lighthouse 复检 ≥ 90；人工验收清单通过 |

M0–M4 期间**每个里程碑结束给你：可运行版本 + 关键截图 + 一条可复制的启动命令**。每个里程碑都是一次独立的小胜利，中途叫停也不会有半成品烂尾。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 中文字体子集体积（Noto Sans SC 全量 ~10MB） | 构建期按常用字集子集化到 ~2MB，且只在首次点导出时懒加载 |
| HTML 预览与 PDF 双渲染不一致 | 同一数据源 + 同一布局规范（mm 制），M2 用截图逐模板比对；兜底方案切"预览即 PDF"模式 |
| 手机 iframe/PDF 预览兼容性 | 移动端预览用 PNG 快照兜底，导出功能本身不依赖 iframe |
| localStorage 被浏览器清理 | 醒目提示"导出 JSON 备份"，编辑器常驻保存状态 |
